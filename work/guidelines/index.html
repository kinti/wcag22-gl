As Pautas de Accesibilidade para o Contido Web (WCAG) 2.2 cobren unha ampla gama de recomendacións para facer o contido web máis accesible. Seguir estas pautas fará o contido máis accesible a unha gama máis ampla de persoas con discapacidade, incluíndo adaptacións para cegueira e baixa visión, xordeira e perda auditiva, mobilidade limitada, discapacidades da fala, fotosensibilidade e combinacións destas, e algunha adaptación para discapacidades da aprendizaxe e limitacións cognitivas; pero non abordará todas as necesidades dos usuarios con estas discapacidades. Estas pautas abordan a accesibilidade do contido web en calquera tipo de dispositivo (incluíndo ordenadores de sobremesa, portátiles, quioscos e dispositivos móbiles). Seguir estas pautas tamén adoita facer o contido web máis utilizable para as persoas usuarias en xeral.

Os criterios de éxito das WCAG 2.2 redáctanse como declaracións comprobables que non son específicas de tecnoloxía. A orientación sobre como cumprir os criterios de éxito en tecnoloxías específicas, así como a información xeral sobre a interpretación dos criterios de éxito, proporciónase en documentos separados. Véxase a visión xeral das Pautas de Accesibilidade para o Contido Web (WCAG) para unha introdución e ligazóns ao material técnico e educativo das WCAG.

As WCAG 2.2 estenden as Pautas de Accesibilidade para o Contido Web 2.1 [[WCAG21]], publicadas como Recomendación do W3C en xuño de 2018. O contido que cumpre as WCAG 2.2 tamén cumpre as WCAG 2.0 e as WCAG 2.1. O Grupo de Traballo pretende que, para as políticas que requiran conformidade coas WCAG 2.0 ou 2.1, as WCAG 2.2 poidan proporcionar un medio alternativo de conformidade. A publicación das WCAG 2.2 non deprecia nin substitúe as WCAG 2.0 nin as WCAG 2.1. Mentres as WCAG 2.0 e as WCAG 2.1 sigan sendo Recomendacións do W3C, o W3C recomenda o uso das WCAG 2.2 para maximizar a aplicabilidade futura dos esforzos de accesibilidade. O W3C tamén anima a usar a versión máis actual das WCAG ao desenvolver ou actualizar políticas de accesibilidade web.

Para comentar, abra unha incidencia no repositorio GitHub de WCAG do W3C. Aínda que os criterios de éxito propostos neste documento referencian discusións de seguimento de incidencias, o Grupo de Traballo solicita que os comentarios públicos se presenten como novas incidencias, unha por cada comentario discreto. Crear unha conta de GitHub para presentar incidencias é gratuíto. Se presentar incidencias en GitHub non é viable, envíe un correo electrónico a public-agwg-comments@w3.org (arquivo de comentarios).

Introdución

Antecedentes das WCAG 2

As Pautas de Accesibilidade para o Contido Web (WCAG) 2.2 definen como facer o contido web máis accesible para as persoas con discapacidade. A accesibilidade implica unha ampla gama de discapacidades, incluíndo discapacidades visuais, auditivas, físicas, da fala, cognitivas, da lingua, da aprendizaxe e neurolóxicas. Aínda que estas pautas cobren unha ampla gama de cuestións, non poden abordar as necesidades das persoas con todos os tipos, graos e combinacións de discapacidade. Estas pautas tamén fan o contido web máis utilizable para as persoas maiores con capacidades cambiantes debido ao envellecemento e adoitan mellorar a usabilidade para as persoas usuarias en xeral.

As WCAG 2.2 desenvólvense a través do proceso do W3C en cooperación con persoas e organizacións de todo o mundo, co obxectivo de proporcionar un estándar compartido de accesibilidade de contido web que satisfaga as necesidades de persoas, organizacións e gobernos internacionalmente. As WCAG 2.2 constrúen sobre as WCAG 2.0 [[WCAG20]] e as WCAG 2.1 [[WCAG21]], que á súa vez se construíron sobre as WCAG 1.0 [[WAI-WEBCONTENT]], e están deseñadas para aplicarse amplamente a diferentes tecnoloxías web agora e no futuro, e para ser comprobables cunha combinación de probas automatizadas e avaliación humana. Para unha introdución ás WCAG, véxase a visión xeral das Pautas de Accesibilidade para o Contido Web (WCAG).

Atopáronse desafíos significativos ao definir criterios adicionais para abordar as discapacidades cognitivas, da lingua e da aprendizaxe, incluíndo un prazo curto de desenvolvemento así como desafíos para acadar o consenso sobre a comprobabilidade, a implementabilidade e as consideracións internacionais das propostas. O traballo continuará nesta área en versións futuras das WCAG. Animamos ás persoas autoras a consultar a nosa orientación complementaria sobre como mellorar a inclusión das persoas con discapacidade, incluíndo discapacidades da aprendizaxe e cognitivas, persoas con baixa visión, e máis.

A accesibilidade web non depende só do contido accesible, senón tamén dos navegadores web accesibles e doutros axentes de usuario. As ferramentas de autoría tamén teñen un papel importante na accesibilidade web. Para unha visión xeral de como estes compoñentes do desenvolvemento e da interacción web funcionan xuntos, véxase:

  • Compoñentes esenciais da accesibilidade web
  • Visión xeral das Pautas de Accesibilidade de Axentes de Usuario (UAAG)
  • Visión xeral das Pautas de Accesibilidade de Ferramentas de Autoría (ATAG)

Cando este documento se refire ás WCAG 2, enténdese calquera e todas as versións das WCAG que comezan por 2.

Niveis de orientación das WCAG 2

As persoas e organizacións que usan as WCAG varían amplamente e inclúen deseñadores e desenvolvedores web, responsables de políticas, axentes de compra, docentes e estudantes. Para satisfacer as necesidades variables desta audiencia, proporciónanse varios niveis de orientación, incluíndo principios globais, pautas xerais, criterios de éxito comprobables e unha rica colección de técnicas suficientes, técnicas consultivas e fallos comúns documentados con exemplos, ligazóns a recursos e código.

  • Principios - Na cúspide están catro principios que proporcionan o fundamento da accesibilidade web: perceptible, operable, comprensible e robusto. Véxase tamén Comprender os catro principios de accesibilidade.

  • Pautas - Baixo os principios están as pautas. As 13 pautas proporcionan os obxectivos básicos cara aos que as persoas autoras deben traballar para facer o contido máis accesible para as persoas usuarias con diferentes discapacidades. As pautas non son comprobables, pero proporcionan o marco e os obxectivos globais que axudan as persoas autoras a entender os criterios de éxito e a implementar mellor as técnicas.

  • Criterios de Éxito - Para cada pauta, proporciónanse criterios de éxito comprobables que permiten usar as WCAG 2.2 onde os requisitos e as probas de conformidade sexan necesarios, como en especificacións de deseño, compras, regulación e acordos contractuais. Para satisfacer as necesidades de diferentes grupos e situacións, defínense tres niveis de conformidade: A (o máis baixo), AA e AAA (o máis alto). Pódese atopar información adicional sobre os niveis das WCAG en Comprender os niveis de conformidade.

  • Técnicas Suficientes e Consultivas - Para cada unha das pautas e dos criterios de éxito do propio documento das WCAG 2.2, o grupo de traballo tamén documentou unha ampla variedade de técnicas. As técnicas son informativas e caen en dúas categorías: as que son suficientes para cumprir os criterios de éxito e as que son consultivas. As técnicas consultivas van máis alá do requirido polos criterios de éxito individuais e permiten ás persoas autoras abordar mellor as pautas. Algunhas técnicas consultivas abordan barreiras de accesibilidade que non están cubertas polos criterios de éxito comprobables. Onde se coñecen fallos comúns, tamén se documentan. Véxase tamén Técnicas suficientes e consultivas en Comprender as WCAG 2.2.

Todos estes niveis de orientación (principios, pautas, criterios de éxito e técnicas suficientes e consultivas) funcionan xuntos para proporcionar orientación sobre como facer o contido máis accesible. Anímase ás persoas autoras a ver e aplicar todos os niveis que poidan, incluíndo as técnicas consultivas, para abordar do mellor xeito posible as necesidades da gama máis ampla posible de persoas usuarias.

Téñase en conta que mesmo o contido que cumpre ao nivel máis alto (AAA) non será accesible para as persoas con todos os tipos, graos ou combinacións de discapacidade, particularmente nas áreas cognitiva, da lingua e da aprendizaxe. Anímase ás persoas autoras a considerar a gama completa de técnicas, incluíndo as consultivas, Making Content Usable for People with Cognitive and Learning Disabilities, así como a buscar consello pertinente sobre as mellores prácticas actuais para asegurar que o contido web sexa accesible, na medida do posible, para esta comunidade. Os metadatos poden axudar ás persoas usuarias a atopar o contido máis axeitado para as súas necesidades.

Outros documentos, chamados documentos de apoio, baséanse no documento das WCAG 2.2 e abordan outros propósitos importantes, incluíndo a posibilidade de actualizarse para describir como se aplicarían as WCAG con novas tecnoloxías. Entre os documentos de apoio inclúense:

Inclúe contido das WCAG 2.0, 2.1 e 2.2, e pódese filtrar de moitas maneiras para axudar as persoas autoras a centrarse no contido relevante.

  2. Comprender as WCAG 2.2 - Unha guía para entender e implementar as WCAG 2.2. Hai un breve documento "Comprender" para cada pauta e criterio de éxito das WCAG 2.2, así como para os temas clave.

  3. Técnicas para as WCAG 2.2 - Unha colección de técnicas e fallos comúns, cada unha nun documento separado que inclúe unha descrición, exemplos, código e probas.

  4. Os documentos WCAG 2 - Unha breve introdución aos documentos de apoio das WCAG 2 e á orientación complementaria.

  5. Que hai de novo nas WCAG 2.2 presenta os novos criterios de éxito con citas de persoas que ilustran os problemas de accesibilidade.

Véxase a visión xeral das Pautas de Accesibilidade para o Contido Web (WCAG) para unha descrición do material de apoio das WCAG 2.2, incluíndo os recursos educativos relacionados coas WCAG 2. Os recursos adicionais que cobren temas como o caso de negocio da accesibilidade web, a planificación da implementación para mellorar a accesibilidade dos sitios web e as políticas de accesibilidade están listados en Recursos WAI.

Requisitos das WCAG 2.2

As WCAG 2.2 cumpren un conxunto de requisitos das WCAG 2.2 que, á súa vez, herdan requisitos de versións anteriores das WCAG 2. Os requisitos estruturan o marco global das pautas e aseguran a compatibilidade cara atrás. O Grupo de Traballo tamén usou un conxunto menos formal de criterios de aceptación para os criterios de éxito, para axudar a asegurar que os criterios de éxito sexan similares en estilo e calidade aos das WCAG 2.0. Estes requisitos restrinxiron o que podía incluírse nas WCAG 2.2. Esta restrición foi importante para preservar a súa natureza de versión puntual das WCAG 2.

Comparación coas WCAG 2.1

As WCAG 2.2 iniciáronse co obxectivo de continuar o traballo das WCAG 2.1: mellorar a orientación de accesibilidade para tres grupos principais: persoas usuarias con discapacidades cognitivas ou da aprendizaxe, persoas usuarias con baixa visión e persoas usuarias con discapacidades en dispositivos móbiles. Propuxéronse e avaliaronse moitas maneiras de satisfacer estas necesidades, e o Grupo de Traballo refinou un conxunto delas. Os requisitos estruturais herdados das WCAG 2.0, a claridade e o impacto das propostas e o prazo levaron ao conxunto final de criterios de éxito incluídos nesta versión. O Grupo de Traballo considera que as WCAG 2.2 avanzan incrementalmente na orientación de accesibilidade de contido web para todas estas áreas, pero subliña que estas pautas non satisfán todas as necesidades dos usuarios.

As WCAG 2.2 constrúen sobre as WCAG 2.1 e son compatibles cara atrás con elas, o que significa que as páxinas web que cumpren as WCAG 2.2 son polo menos tan accesibles como as páxinas que cumpren as WCAG 2.1. Engadíronse requisitos que se constrúen sobre a 2.1 e a 2.0. As WCAG 2.2 eliminaron un criterio de éxito, 4.1.1 Análise. As persoas autoras requiridas por política para cumprir as WCAG 2.0 ou 2.1 poderán actualizar o contido ás WCAG 2.2, pero pode que necesiten seguir probando e informando o 4.1.1. As persoas autoras que sigan máis dunha versión das pautas deberían coñecer as seguintes adicións.

Novas funcionalidades nas WCAG 2.2

As WCAG 2.2 estenden as WCAG 2.1 engadindo novos criterios de éxito, definicións para soportalos e pautas para organizar as adicións. Este enfoque aditivo axuda a deixar claro que os sitios que cumpren as WCAG 2.2 tamén cumpren as WCAG 2.1. O Accessibility Guidelines Working Group recomenda que os sitios adopten as WCAG 2.2 como o seu novo obxectivo de conformidade, incluso se as obrigas formais mencionan versións anteriores, para proporcionar unha accesibilidade mellorada e anticipar futuros cambios de política.

Os seguintes criterios de éxito son novos nas WCAG 2.2:

  • 2.4.11 Foco Non Ocultado (Mínimo) (AA)
  • 2.4.12 Foco Non Ocultado (Mellorado) (AAA)
  • 2.4.13 Aparencia do Foco (AAA)
  • 2.5.7 Movementos de Arrastre (AA)
  • 2.5.8 Tamaño do Obxectivo (Mínimo) (AA)
  • 3.2.6 Axuda Consistente (A)
  • 3.3.7 Entrada Redundante (A)
  • 3.3.8 Autenticación Accesible (Mínimo) (AA)
  • 3.3.9 Autenticación Accesible (Mellorado) (AAA)

Os novos criterios de éxito poden referir novos termos que tamén se engadiron ao glosario e que forman parte dos requisitos normativos dos criterios de éxito.

As WCAG 2.2 tamén introducen novas seccións que detallan aspectos da especificación que poden impactar na privacidade e na seguridade.

Numeración nas WCAG 2.2

Para evitar confusión nas persoas implementadoras para as cales a compatibilidade cara atrás coas versións das WCAG 2 é importante, os novos criterios de éxito das WCAG 2.2 engadíronse ao final do conxunto de criterios de éxito dentro da súa pauta. Isto evita a necesidade de cambiar o número de sección dos criterios de éxito das WCAG 2, que se causaría ao inserir novos criterios de éxito entre criterios de éxito existentes na pauta, pero significa que os criterios de éxito de cada pauta xa non están agrupados por nivel de conformidade. A orde dos criterios de éxito dentro de cada pauta non implica información sobre o nivel de conformidade; só o indicador de nivel de conformidade (A / AA / AAA) no propio criterio de éxito indica isto. A Referencia rápida das WCAG 2.2 proporcionará un xeito de ver os criterios de éxito agrupados por nivel de conformidade, xunto con moitas outras opcións de filtro e ordenación.

Conformidade coas WCAG 2.2

As WCAG 2.2 usan o mesmo modelo de conformidade que as WCAG 2.0. Preténdese que os sitios que cumpren as WCAG 2.2 tamén cumpran as WCAG 2.0 e as WCAG 2.1, o que significa que cumpren os requisitos de calquera política que refira as WCAG 2.0 ou as WCAG 2.1, mentres satisfacen mellor as necesidades das persoas usuarias na Web actual.

Versións posteriores das pautas de accesibilidade

En paralelo coas WCAG 2.2, o Accessibility Guidelines Working Group está a desenvolver outra versión maior das pautas de accesibilidade. Espérase que o resultado deste traballo sexa unha reestruturación máis substancial da orientación de accesibilidade web da que sería realista para versións puntuais das WCAG 2. O traballo segue unha metodoloxía de deseño centrada na persoa usuaria e enfocada á investigación para producir o resultado máis efectivo e flexible, incluíndo os roles da autoría de contido, o soporte de axentes de usuario e o soporte de ferramentas de autoría. Este é un esforzo de varios anos, así que as WCAG 2.2 son necesarias como medida intermedia para proporcionar orientación de accesibilidade web actualizada que reflicta os cambios na web desde a publicación das WCAG 2.0. O Grupo de Traballo tamén pode desenvolver versións intermedias adicionais, continuando coas WCAG 2.2, nun prazo curto similar para proporcionar soporte adicional mentres se completa a versión maior.

Perceptible

A información e os compoñentes da interfaz de usuario deben presentarse ás persoas usuarias en formas que poidan percibir.

Alternativas Textuais

Proporcionar alternativas textuais para todo contido non textual, de xeito que poida converterse en outras formas que as persoas necesiten, como impresión grande, braille, fala, símbolos ou lingua máis sinxela.

Medios Tempodependentes

Proporcionar alternativas para os medios tempodependentes.

Adaptable

Crear contido que poida presentarse de diferentes xeitos (por exemplo, unha disposición máis sinxela) sen perder información nin estrutura.

Distinguible

Facilitar que as persoas usuarias vexan e oian o contido, incluíndo separar o primeiro plano do fondo.

Operable

Os compoñentes da interfaz de usuario e a navegación deben ser operables.

Accesible por Teclado

Facer toda a funcionalidade dispoñible desde un teclado.

Tempo Suficiente

Proporcionar ás persoas usuarias tempo suficiente para ler e usar o contido.

Convulsións e Reaccións Físicas

Non deseñar contido de xeito que se saiba que causa convulsións ou reaccións físicas.

Navegable

Proporcionar xeitos de axudar ás persoas usuarias a navegar, atopar contido e determinar onde están.

Modalidades de Entrada

Facilitar que as persoas usuarias operen a funcionalidade a través de varias entradas máis alá do teclado.

Comprensible

A información e o funcionamento da interfaz de usuario deben ser comprensibles.

Lexible

Facer o contido textual lexible e comprensible.

Previsible

Facer que as páxinas web aparezan e funcionen de xeitos previsibles.

Asistencia de Entrada

Axudar ás persoas usuarias a evitar e corrixir erros.

Robusto

O contido debe ser o bastante robusto para que poida ser interpretado por unha ampla variedade de axentes de usuario, incluíndo as tecnoloxías de asistencia.

Compatible

Maximizar a compatibilidade cos axentes de usuario actuais e futuros, incluíndo as tecnoloxías de asistencia.

Conformidade

Esta sección lista os requisitos de conformidade coas WCAG 2.2. Tamén dá información sobre como facer declaracións de conformidade, que son opcionais. Finalmente, describe que significa ter compatibilidade coas tecnoloxías de asistencia, xa que a conformidade só pode basearse en xeitos de usar tecnoloxías con compatibilidade coas tecnoloxías de asistencia. Comprender a conformidade inclúe máis explicacións do concepto de compatibilidade coas tecnoloxías de asistencia.

Interpretación dos Requisitos Normativos

O contido principal das WCAG 2.2 é normativo e define requisitos que impactan nas declaracións de conformidade. O material introdutorio, os apéndices, as seccións marcadas como "non normativas", os diagramas, os exemplos e as notas son informativos (non normativos). O material non normativo proporciona información consultiva que axuda a interpretar as pautas pero non crea requisitos que impacten nunha declaración de conformidade.

As palabras clave MAY, MUST, MUST NOT, NOT RECOMMENDED, RECOMMENDED, SHOULD e SHOULD NOT han interpretarse como se describe en [[RFC2119]].

Requisitos de Conformidade

Para que unha páxina web cumpra as WCAG 2.2, deben cumprirse todos os seguintes requisitos de conformidade:

Nivel de Conformidade

Cúmprese enteiramente un dos seguintes niveis de conformidade.

  • Para a conformidade de Nivel A (o nivel mínimo de conformidade), a páxina web cumpre todos os criterios de éxito de Nivel A, ou proporciona unha versión alternativa conforme.
  • Para a conformidade de Nivel AA, a páxina web cumpre todos os criterios de éxito de Nivel A e de Nivel AA, ou proporciona unha versión alternativa conforme de Nivel AA.
  • Para a conformidade de Nivel AAA, a páxina web cumpre todos os criterios de éxito de Nivel A, Nivel AA e Nivel AAA, ou proporciona unha versión alternativa conforme de Nivel AAA.

Aínda que a conformidade só pode acadarse nos niveis declarados, anímase ás persoas autoras a informar (na súa declaración) de calquera progreso cara ao cumprimento de criterios de éxito de todos os niveis máis alá do nivel de conformidade acadado.

Non se recomenda requirir a conformidade de Nivel AAA como política xeral para sitios enteiros, porque non é posible satisfacer todos os criterios de éxito de Nivel AAA para algún contido.

Páxinas completas

A conformidade (e o nivel de conformidade) aplícase só a páxinas web completas, e non pode acadarse se se exclúe parte dunha páxina web.

Para os efectos de determinar a conformidade, as alternativas a parte do contido dunha páxina considéranse parte da páxina cando as alternativas poden obterse directamente desde a páxina, por exemplo, unha descrición longa ou unha presentación alternativa dun vídeo.

As persoas autoras de páxinas web que non poden cumprir por contido fóra do control da persoa autora poden considerar unha Declaración de Conformidade Parcial.

Unha páxina completa inclúe cada variación da páxina que a páxina presenta automaticamente para varios tamaños de pantalla (por exemplo, variacións nunha páxina web responsiva). Cada unha destas variacións debe cumprir (ou debe ter unha versión alternativa conforme) para que a páxina enteira cumpra.

Procesos completos

Cando unha páxina web é unha dunha serie de páxinas web que presentan un proceso (é dicir, unha secuencia de pasos que deben completarse para lograr unha actividade), todas as páxinas web do proceso cumpren ao nivel especificado ou mellor. (A conformidade non é posible nun nivel particular se calquera páxina do proceso non cumpre nese nivel ou mellor.)

Unha tenda en liña ten unha serie de páxinas que se usan para seleccionar e comprar produtos. Todas as páxinas da serie, do principio ao fin (pago), cumpren para que calquera páxina que forme parte do proceso cumpra.

Só Xeitos de Usar Tecnoloxías con Compatibilidade coas Tecnoloxías de Asistencia

O cumprimento dos criterios de éxito só se basea en xeitos de usar tecnoloxías con compatibilidade coas tecnoloxías de asistencia. Calquera información ou funcionalidade proporcionada dun xeito que non teña compatibilidade coas tecnoloxías de asistencia tamén está dispoñible nun xeito que teña compatibilidade coas tecnoloxías de asistencia. (Véxase Comprender a compatibilidade coas tecnoloxías de asistencia.)

Non Interferencia

Se as tecnoloxías se usan dun xeito que non ten compatibilidade coas tecnoloxías de asistencia, ou se se usan dun xeito non conforme, non bloquean a capacidade das persoas usuarias para acceder ao resto da páxina. Ademais, a páxina web como un todo segue cumprindo os requisitos de conformidade en cada unha das seguintes condicións:

  1. cando calquera tecnoloxía na que non se basea está activada nun axente de usuario,
  2. cando calquera tecnoloxía na que non se basea está desactivada nun axente de usuario, e
  3. cando calquera tecnoloxía na que non se basea non é compatible cun axente de usuario

Ademais, os seguintes criterios de éxito aplícanse a todo o contido da páxina, incluíndo o contido no que non se basea doutro xeito a conformidade, porque o incumprimento deles podería interferir en calquera uso da páxina:

  • 1.4.2 - Control do Audio,
  • 2.1.2 - Sen Trampa de Teclado,
  • 2.3.1 - Tres Flash ou Por Debaixo do Limiar, e
  • 2.2.2 - Pausar, Deter, Ocultar.

Se unha páxina non pode cumprir (por exemplo, unha páxina de proba de conformidade ou unha páxina de exemplo), non pode incluírse no alcance de conformidade nin nunha declaración de conformidade.

Para máis información, incluíndo exemplos, véxase Comprender os requisitos de conformidade.

Declaracións de Conformidade (Opcionais)

A conformidade defínese só para páxinas web. Non obstante, pode facerse unha declaración de conformidade que cubra unha páxina, unha serie de páxinas ou múltiples páxinas web relacionadas.

Compoñentes Requiridos dunha Declaración de Conformidade

As declaracións de conformidade non son requiridas. As persoas autoras poden cumprir as WCAG 2.2 sen facer unha declaración. Non obstante, se se fai unha declaración de conformidade, a declaración debe incluír a seguinte información:

  1. Data da declaración
  2. Título, versión e URI das pautas "Web Content Accessibility Guidelines (WCAG) 2.2 en https://www.w3.org/TR/WCAG22/"
  3. Nivel de conformidade cumprido: (Nivel A, AA ou AAA)

  4. Unha descrición concisa das páxinas web, como unha lista dos URIs para os cales se fai a declaración, incluíndo se os subdominios se inclúen na declaración.

    As páxinas web poden describirse por lista ou por unha expresión que describe todos os URIs incluídos na declaración.

    Os produtos baseados en web que non teñen URI antes da instalación no sitio web do cliente poden ter unha declaración de que o produto cumpriría unha vez instalado.

  5. Unha lista das tecnoloxías de contido web nas que se basea.

Se se usa un logo de conformidade, constitúe unha declaración e debe acompañarse dos compoñentes requiridos dunha declaración de conformidade listados arriba.

Compoñentes Opcionais dunha Declaración de Conformidade

Ademais dos compoñentes requiridos dunha declaración de conformidade de arriba, considere proporcionar información adicional para axudar ás persoas usuarias. A información adicional recomendada inclúe:

  • Unha lista dos criterios de éxito máis alá do nivel de conformidade declarado que se cumpriron. Esta información debería proporcionarse nunha forma que as persoas usuarias poidan usar, preferiblemente metadatos lexibles por máquina.
  • Unha lista das tecnoloxías específicas que están "usadas pero nas que non se basea".
  • Unha lista de axentes de usuario, incluíndo as tecnoloxías de asistencia que se usaron para probar o contido.
  • Unha lista das características específicas de accesibilidade do contido, proporcionada en metadatos lexibles por máquina.
  • Información sobre calquera paso adicional tomado que vaia máis alá dos criterios de éxito para mellorar a accesibilidade.
  • Unha versión en metadatos lexibles por máquina da lista das tecnoloxías específicas nas que se basea.
  • Unha versión en metadatos lexibles por máquina da declaración de conformidade.

Consulte Comprender as declaracións de conformidade para máis información e exemplos de declaracións de conformidade.

Consulte Comprender os metadatos para máis información sobre o uso de metadatos nas declaracións de conformidade.

Declaración de Conformidade Parcial - Contido de Terceiros

As páxinas web que máis tarde terán contido adicional engadido poden usar unha "declaración de conformidade parcial". Por exemplo, un programa de correo, un blog, un artigo que permite ás persoas usuarias engadir comentarios ou aplicacións que admiten contido contribuído polo usuario. Outro exemplo sería unha páxina, como un portal ou sitio de noticias, composta de contido agregado de múltiples colaboradores, ou sitios que inseren automaticamente contido doutras fontes ao longo do tempo, como cando se inseren publicidades dinamicamente.

Nestes casos, non é posible saber no momento da publicación orixinal cal será o contido non controlado das páxinas. É importante notar que o contido non controlado pode afectar tamén á accesibilidade do contido controlado. Hai dúas opcións dispoñibles:

  1. Pode facerse unha determinación de conformidade baseándose no mellor coñecemento. Se unha páxina deste tipo se monitoriza e repara (o contido non conforme elimínase ou tráese á conformidade) dentro de dous días hábiles, pode facerse unha determinación ou declaración de conformidade, xa que, agás polos erros no contido contribuído externamente que se corrixen ou eliminan ao atopalos, a páxina cumpre. Non pode facerse ningunha declaración de conformidade se non é posible monitorizar ou corrixir o contido non conforme;

    OU

  2. Pode facerse unha "declaración de conformidade parcial" de que a páxina non cumpre, pero podería cumprir se se retirasen certas partes. A forma desa declaración sería: "Esta páxina non cumpre, pero cumpriría as WCAG 2.2 ao nivel X se se retirasen as seguintes partes de fontes non controladas". Ademais, o seguinte tamén sería verdadeiro para o contido non controlado que se describe na declaración de conformidade parcial:

    1. Non é contido que estea baixo o control da persoa autora.
    2. Descríbese dun xeito que as persoas usuarias poden identificar (por exemplo, non poden describirse como "todas as partes que non controlamos" agás que estean claramente marcadas como tal.)

Declaración de Conformidade Parcial - Lingua

Pode facerse unha "declaración de conformidade parcial debido á lingua" cando a páxina non cumpre, pero cumpriría se existise compatibilidade coas tecnoloxías de asistencia para (todas) as linguas usadas na páxina. Rexistro de Cambios

Esta sección mostra os cambios substanciais incorporados nas WCAG 2.2 desde as WCAG 2.1, así como os cambios feitos na 2.2 desde a súa publicación orixinal o 5 de outubro de 2023. As correccións de erratas das WCAG 2.1 tamén se incorporaron nas WCAG 2.2.

O historial de commits completo das WCAG 2.2 está dispoñible.

  • 2020-03-30: Engadiuse Autenticación Accesible (Mínimo).
  • 2020-05-27: Engadiuse Dragging (renomeado despois como Movementos de Arrastre).
  • 2020-07-19: Engadíronse Findable Help (renomeado despois como Axuda Consistente), Pointer Target Spacing (renomeado despois como Tamaño do Obxectivo (Mínimo)) e Entrada Redundante.
  • 2020-08-04: Engadiuse Focus Appearance (Minimum) (renomeado despois como Aparencia do Foco).
  • 2021-09-21: Engadiuse Accessible Authentication (No Exception) (renomeado despois como Autenticación Accesible (Mellorado)).
  • 2022-03-22: Engadiuse Foco Non Ocultado (Mínimo).
  • 2022-05-30: Engadiuse Foco Non Ocultado (Mellorado).
  • 2023-06-05: Engadíronse as seccións de privacidade e seguridade dentro da conformidade.
  • 2024-12-12: Republicáronse as WCAG 2.2, incorporando as seguintes erratas:
    • modificáronse as definicións de único punteiro, usada dun xeito inusual ou restrinxido, animación de movemento e determinado programaticamente
    • modificouse o formato das definicións de cambios de contexto, limiares de flash xeral e de flash vermello, proba de función cognitiva e estrutura
    • retirouse a definición fóra de uso encloses
    • corrixido un erro tipográfico na lista de finalidades de entrada
    • modificouse o formato de Tamaño do Obxectivo (Mínimo) e Autenticación Accesible (Mínimo)
    • modificouse a presentación visual do contido identificado como Novo
    • modificouse a linguaxe sobre dispositivos no Resumo
    • fixéronse cambios editoriais para mellorar o uso consistente das definicións nos criterios de éxito
    • fixéronse cambios editoriais para mellorar o uso consistente dos termos success criteria/criterion, web, website e web page
